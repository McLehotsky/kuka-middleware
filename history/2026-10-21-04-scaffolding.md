# Scaffolding – backend, frontend, Docker, PRODUCT.md

## Why

User Story 4.1: the whole solution should start with one command and use a persistent database whose schema matches the ERD. Every later phase builds on this skeleton.

  - Q4 and Q5 decided.
  - Physical schema: snake_case names, nullability, string lengths, delete behaviour.
  - Approved dependencies with exact versions.
  - Test and audit policy.
  - Q10 (container hardening) added.
  - The mockups' visual language is binding.
- `CLAUDE.md`:
  - Real commands for backend, frontend and Docker.

- Local tools installed with winget: .NET SDK 10.0.402 and Node 24.20.0 LTS.

**backend-expert** (`backend/`)
- `KukaMiddleware.slnx`, `global.json` (SDK 10.0.402, Microsoft.Testing.Platform runner), `Directory.Build.props` (net10.0, nullable, warnings as errors), `.config/dotnet-tools.json` (dotnet-ef 10.0.13).

**frontend-expert** (`frontend/`)

**ops-infra-expert** (`docker/`)

  - Only web is published.
- `.env.example`: placeholders only.

## Decisions

- **Q4:**
  - Backend tests use xUnit + NSubstitute with plain `Assert`.
  - Frontend tests use Vitest, only for composables and pure functions.
  - The VSTest packages were removed, because `dotnet test` runs on Microsoft.Testing.Platform.
- **Q5:** frontend state lives in composables, with no Pinia. Styling is plain scoped CSS with tokens, with no Tailwind and no UI library.
- **Schema:**
  - snake_case names.
  - Nullable only for values that arrive later.
  - Cascade for mission steps and history, Restrict for api_client and robot, SetNull for the audit log.
  - `UNIQUE (mission_id, sequence)` added (not in the wiki).
  - `mission_code` is generated by the middleware.
- **New dependency** `Microsoft.EntityFrameworkCore.Relational` 10.0.13 (approved). It keeps the EF design-time assemblies out of the runtime image: the publish output dropped from 32 MB to 7.1 MB.
- **Local dev without Docker:** `dotnet run` on port 5063 and `npm run dev`. The connection string goes in user secrets.
- **Audit:**
  - The audit covers runtime packages only.
  - Known dev-only advisory: GHSA-vfj7-8cjw-p6xm (`braces`).
- **Postponed to phase 8 (Q10):** non-root nginx and an api healthcheck.
- **Design:**
  - The mockups' visual language is binding.
  - `PRODUCT.md` is written now.
  - `DESIGN.md` is derived from the mockups when the first screen is built.
  - UI copy is in English.

## Review

The first review returned **changes required**:
- Blocker: `dotnet test` exited 8.
- Major: the VSTest packages were still referenced.
- Major: EF design-time assemblies ended up in the runtime image.
- Minor: a dev DB password in `appsettings.Development.json`.
- Minor: the dev proxy port didn't match the API port.
- Minor: nginx sent no security headers.

All of these were fixed by their owners. On the re-check the verdict was **approve**.

| Criterion (4.1) | Status |
|---|---|
| `docker compose up` starts web, api and PostgreSQL | not verifiable yet (CI) – static review passed |
| DB schema matches the ERD and is created by an EF Core migration on API startup | met – `InitialCreate` SQL matches §7 table by table, no pending model changes |
| Data survives container restarts | not verifiable yet (CI) – named volume at the correct PG 18 path |

Accepted deviations:
- No DbSets, so the tables get singular snake_case names.
- MTP is enabled through `global.json`.
- The dev-only npm advisory.
