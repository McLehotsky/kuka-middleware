# Refresh the automatic CD trigger

## Why

After merging PR #12, `kuka-middleware-ci` ran green on main (`#20261126.9`, and manually `#20261126.11`), but `kuka-middleware-cd` was never queued. A manual CD run (`#20261126.2`, resource `ci/20261126.10`) deployed successfully, so only the pipeline completion trigger is missing. The CD pipeline was created while the CI pipeline was still named `McLehotsky.kuka-middleware-ci`; the CD default branch is `refs/heads/main` and no Build completion trigger overrides the YAML. Azure registers YAML pipeline-resource triggers when it reads the YAML from the default branch, so a change to `cd.yml` on main should register the trigger against the renamed CI pipeline (user decision 2026-11-26: try this before restructuring).

## What changed

**main session**
- `ci-cd/cd.yml`: pipeline resource branch filter written as `refs/heads/main` with a comment; behaviour unchanged.
- `implementation.md`, `history/README.md`.

## Decisions

- Try the cheap refresh first. If CD still does not start after the next CI run on main, the fallback is a Deploy stage in `ci.yml` sharing the steps with `cd.yml` through a template (needs user approval).

## Review

One-line trigger change; no reviewer run. The merge of this PR is the test.

## Out of scope / open items

- If the refresh does not work: Deploy stage fallback (above).
- GitHub ruleset on main: needs the repository owner (the user's account has push, not admin).
