# Azure Pipelines CI for GitHub

## Why

The user connected the GitHub repository in Azure DevOps and requested a YAML file to select in the Configure screen. Backlog 4.3 requires builds, unit tests, static analysis, published test results and a required successful pipeline before merging.

## What changed

- `ci-cd/azure-pipelines.yml`: explicit GitHub push/all-branch and PR-to-main triggers; independent backend/frontend jobs on Microsoft-hosted Ubuntu 24.04.
- Backend: pinned SDK from global.json, restore, Release build with .NET analyzers and warnings as errors, Microsoft.Testing.Platform tests and xUnit XML publication.
- Frontend: pinned Node 24.22.1, npm ci, type check, ESLint, Vitest/JUnit, production build.
- Missing reports, failed tests and failed checks fail the job. Results are published after failed test runs too.
- `ci-cd/README.md`: GitHub App authorization, YAML selection, hosted-agent prerequisite, first run and GitHub branch protection.
- Specification/roadmap updated; unused `.gitkeep` removed.

## Decisions

- Use built-in Azure tasks and existing dependencies only. No new NuGet/npm packages, third-party Azure extensions, database, Docker stack, Fleet credentials or deployment action.
- xUnit 4.0.2 requires `--report-xunit-xml --report-xunit-xml-filename`; confirmed using the installed runner help. Older documentation's `--report-xunit` switches were rejected during verification and corrected before completion.
- Keep 4.3 partial until the actual Azure run, result publication and GitHub required status-check policy are verified.

## Review

Independent reviewer approved YAML/README for correctness, failure handling, triggers, task inputs and scope. No actionable findings remain after checking the installed reporter flags. Azure-specific runtime behaviour remains explicitly unverified.

## Out of scope / open items

- Azure Configure currently warns that the Azure Pipelines GitHub App is not installed for this repository. Owner/admin authorization may be required.
- Hosted-agent capacity, actual Azure execution and GitHub main branch protection require setup in the connected services.
- CD target, deployment secrets and smoke checks remain backlog 4.4. Live KUKA integration is separate from these unit checks.

## Verification

- YAML parsed successfully; checked both jobs, failure flags and lack of ignored failures. `git diff --check` passed.
- Executed the actual YAML command strings in clean temporary containers using existing SDK/Node image versions, outside the host's older toolchains.
- Backend restore and Release build/analyzers: 0 warnings/errors. Corrected report command: 134 tests passed, 0 failed; generated xUnit XML parsed as `assemblies` with 134 cases.
- Frontend install, type check, lint, 95 tests and production build passed. JUnit XML parsed with 95 tests and 0 failures. Also confirmed creation of a previously nonexistent output directory.
- Built-in Azure installer/publisher tasks cannot be run by this local check; verify those in the first Azure pipeline run.
