# Run the app in Docker Compose (4.1)

## Why

The Dockerfiles and the compose file were written in phase 4 but never run, because Docker was not installed on the dev PC. Docker Desktop now runs, so backlog 4.1 can be proven for real. The user decided the app runs **only** in Docker Compose from now on; the local PostgreSQL + user-secrets + `dotnet run` + Vite dev server flow is dropped.

## What changed

**main session**
- `docker/.env` created locally with a random password (git-ignored, never committed or printed).
- `LOCAL-DEVELOPMENT.md` rewritten for the Docker-only flow: prerequisites, `.env`, `up -d --build` (also after code changes), logs, `psql` in the container, reset with `down -v`, host checks, troubleshooting.
- `CLAUDE.md` (user-approved): Commands without user-secrets, `dotnet run` and the dev server; `config --quiet`; database shell row; Verify step uses the rebuilt Docker stack; frontend convention "proxied by nginx".
- `README.md`: Getting started summary.
- `.claude/system-definition.md`: §3 runtime line; §14 "Docker scope" decisions; the phase 6 local-PostgreSQL line marked superseded; open items Q16 (nginx 502 wording), Q17 (EF command logging), Q18 (web port on all interfaces).

**ops-infra-expert** (`docker/`)
- `docker-compose.yml`: postgres healthcheck `pg_isready -h 127.0.0.1` (TCP, so it can't pass during first init before the server accepts connections); `Gss Encryption Mode=Disable` in the api connection string (Npgsql 10 probed `libgssapi_krb5.so.2`, which the aspnet image doesn't have).
- `.env.example`: the password must not contain `;` or `$`.
- `start.bat` (user request): checks Docker is running, creates `docker/.env` from the template with a random hex password if it is missing (an existing file is left alone), then runs `up -d --build` and prints the app URL.
- All pinned images exist; no tag changed.

**backend-expert** (`backend/`)
- Removed `<UserSecretsId>` and `Properties/launchSettings.json` (only used by `dotnet run` on 5063).

**frontend-expert** (`frontend/`)
- Removed the Vite `/api` proxy and the `dev` and `preview` scripts; `http.ts` comment.

## Decisions

- Docker only for running the app; code changes are picked up by a manual `docker compose -f docker/docker-compose.yml up -d --build`.
- Builds, unit tests, lint, type check and new migrations stay on the host.
- Port 8080; only `web` is published; PostgreSQL via `docker compose exec postgres psql`.
- Non-root nginx and an api healthcheck (Q10) and CD image names stay in phase 8.
- No default password in compose, so a known password never reaches a real deployment: `docker/.env` is created by `start.bat` with a random password, or copied by hand.
