# CD pipeline to local Docker and Seq logging

## Why

The teacher asked for a CD pipeline on the self-hosted Azure Pipelines agent that deploys the middleware directly to the team's device, and recommended Seq for logging and monitoring (sample project FEI-thridos/ITS). Backlog 4.4 requires an automatic deploy after merge into main, secrets only in secret variables and a smoke check of the web and `/api/health`.

## What changed

**ops-infra-expert**
- `ci-cd/cd.yml` (Azure pipeline `kuka-middleware-cd`), same pool/agent as CI, Windows PowerShell 5.1:
  - triggered by a successful `kuka-middleware-ci` run on `main` (pipeline resource), manual runs allowed; deploys only `refs/heads/main`;
  - checks Docker; validates pipeline variables (no empty, macro, quote, `$`, `#`, whitespace, `;` in DB values; API keys 64 lowercase hex and different; `WebPort` 1024–65535; `DeployPath` canonical, two levels deep, outside the agent work folder, existing folder must hold a previous deploy);
  - `robocopy /MIR` to `DeployPath`, fills `docker/.env.prod` placeholders only in that copy (UTF-8 without BOM, LF, unknown placeholders rejected before filling, no secret fragments in errors);
  - `docker compose build --no-cache` + `up -d` (project `kuka-middleware`, never `down -v`);
  - smoke check `http://127.0.0.1:<WebPort>/`, `/api/health` and Seq, 30 × 5 s, prints `ps` and logs and fails otherwise;
  - always prunes the build cache and dangling images.
- `docker/.env.prod`: committed template with placeholders only.
- `docker/docker-compose.yml`, `docker/.env.example`: service `seq` (`datalust/seq:2026.1.17182`, `127.0.0.1:${SEQ_PORT:-5341}:80`, volume `seq-data`, no login); api depends on seq.
- `ci-cd/README.md`: pool Security > Pipeline permissions for both pipelines, CD variables table with secret flags and no override, DeployPath ACL, Local System and Docker Desktop notes.

**backend-expert**
- `KukaMiddleware.Api.csproj`: `Serilog.AspNetCore` 11.0.0, `Serilog.Sinks.Seq` 9.1.0.
- `Program.cs`: `AddSerilog` from configuration with `Enrich.FromLogContext` instead of `AddJsonConsole`.
- `appsettings.json`: `Serilog` section – compact JSON console and Seq `http://seq:5341`; EF SQL commands, `Microsoft.AspNetCore` and `System.Net.Http` at Warning.

**main session**
- `.claude/system-definition.md` §3 approved dependencies, §6 logging, §10 CD, §14 Q7 and decision "Seq"; `CLAUDE.md` logs and compose row; `LOCAL-DEVELOPMENT.md` Seq URL; `.gitignore` `!docker/.env.prod`; `implementation.md`.

## Decisions

- Teacher style (user decision 2026-11-25): separate `cd.yml`, pipeline variables (secret where sensitive) instead of a variable group, `.env.prod` template with placeholders, `--no-cache` build, `api` depends on `seq`.
- Unlike the teacher, secrets are filled only into `.env.prod` in `DeployPath`, never into appsettings or images.
- Automatic CD after CI on main to meet 4.4 AC1 (teacher runs it manually).
- One shared compose stack for local development and deployment. Port 8080 is taken by another program on the agent PC, so the web port is the pipeline variable `WebPort` (8081 there).
- Seq replaces decision Q6/Q17 "no additional log service"; UI bound to 127.0.0.1 without login.

## Review

First review: changes required.
- Major: the `DeployPath` guard in front of `robocopy /MIR` (run as SYSTEM) accepted `C:\deploy\..\..` (drive root). Fixed with `GetFullPath` canonical check, checks on the normalized path and a previous-deploy marker.
- Minor, fixed: dangling images not pruned; manual deploy from non-main branches; placeholder error could print a password fragment; smoke check via `localhost` instead of `127.0.0.1`; README pool permission, no-override and ACL notes; KUKA secrets noted in §10.
- Kept by decision: `api` depends on `seq`.

Re-check: **approve**. Backend: no findings.
