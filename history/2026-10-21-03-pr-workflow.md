# Pull requests in the workflow

## Why

Until now the user opened and merged every PR on GitHub by hand. The workflow should end with a PR that is ready to review, opened by the agents, so that the user only reads and merges it.

## What changed

- `CLAUDE.md`, Workflow: new step 7 **PR**, where the main session pushes the branch and opens the PR. Step 8 **Close** is now the user reviewing and merging it.
- `CLAUDE.md`, new section **Pull requests**:
  - The main session owns git and `gh`; expert agents and the reviewer never commit, push or open PRs.
  - A PR is opened only after the reviewer approves and the history note is written.
  - Title and body format, with the body built from the history note and the reviewer's acceptance criteria table.
  - The `gh pr create` command.
  - The PR number and URL are written back into the history note and `implementation.md`.
  - Merging happens only when the user says so: a merge commit, no squash, no force-push, no auto-merge.
  - Review feedback is fixed on the same branch.
- `CLAUDE.md`, Git: the remote URL and how to check `gh` (`gh auth status`).
- `.claude/agents/reviewer.md`: the acceptance criteria table is reused in the PR body.
- GitHub CLI installed on this PC with `winget install --id GitHub.cli`.

## Decisions

- Agents open PRs, and only the user merges them, either on GitHub or by saying "merge" in chat.
- PR #1 (README) was opened and merged by the user by hand. This PR is the first one opened with `gh`.

## Review

Not reviewed by the `reviewer` agent because no code changed.

## Out of scope / open items

- `gh auth login` has to be done once per PC by the user.
- Branch protection on `main` is set by the user in GitHub settings.
